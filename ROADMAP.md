# Roadmap DeliveryPulse

Каждый этап завершается отдельным проверяемым результатом. Следующий этап не
должен скрывать незавершённые критерии предыдущего.

## Этап 0. Проектирование

Результат: согласованный аналитический контракт до написания генератора.

Критерии готовности:

- [x] описаны бизнес-задача, границы и пользователи;
- [x] предложена структура проекта;
- [x] определены таблицы, поля, ключи и ограничения;
- [x] определены основные метрики, зерно и правила выборки;
- [x] сформулировано не менее восьми проверяемых гипотез;
- [x] выделены 4–6 гипотез для обязательной глубокой проверки;
- [x] зафиксированы RUB, `Europe/Moscow`, матрица статусов и правила `NULL`;
- [x] зафиксированы правила кроссплатформенности и работы Codex;
- [x] настроен `.gitignore` для локальных и генерируемых артефактов.

## Этап 1. Каркас Python-проекта

Результат: устанавливаемый локальный пакет и минимальный набор инструментов.

Критерии готовности:

- [x] создан `pyproject.toml` с зафиксированными диапазонами зависимостей;
- [x] создан пакет `src/delivery_pulse`;
- [x] единая конфигурация путей реализована через `pathlib.Path`;
- [x] команды установки описаны отдельно для Linux и Windows;
- [x] настроены `pytest`, форматирование и статические проверки;
- [x] базовые проверки запускаются без PostgreSQL, Docker и Bash-зависимости.

## Этап 2. Генерация синтетических данных

Результат: воспроизводимые связанные исходные таблицы.

Критерии готовности:

- [x] генератор принимает seed, период и объём;
- [x] одинаковые параметры дают одинаковые данные;
- [x] данные соответствуют модели и не содержат реальных сущностей;
- [x] бизнес-зависимости и аномалии документированы;
- [x] не все гипотезы подтверждаются; предусмотрены исчезающие после контроля и
  сегментные эффекты;
- [x] созданы стартовые пробеги и предпериодное обслуживание автомобилей;
- [x] операционные перегрузы отделены от искусственных дефектов;
- [x] технический quality issue manifest воспроизводим и доступен только тестам;
- [x] есть малый профиль для тестов и основной профиль для анализа;
- [x] данные записываются в `data/raw/` и не попадают в Git;
- [x] тесты проверяют детерминированность и ссылочную целостность.

## Этап 3. Контроль качества данных

Результат: автоматический отчёт о пригодности данных к анализу.

Критерии готовности:

- [x] проверяются схема, ключи, пропуски, диапазоны и категории;
- [x] проверяются временные и межтабличные бизнес-правила;
- [x] критические ошибки отделены от предупреждений;
- [x] контролируемые дефекты обнаруживаются тестами;
- [x] manifest не используется аналитическим кодом и не попадает в витрины;
- [x] проверяется матрица статусов и семантика финансовых `NULL`/`0`;
- [x] ноутбук качества объясняет влияние дефектов на метрики;
- [x] правила исправления не уничтожают исходные данные.

## Этап 4. DuckDB и SQL-слой

Результат: локальная аналитическая база и воспроизводимые витрины.

Критерии готовности:

- [x] DDL согласован с `docs/data_model.md`;
- [x] загрузка таблиц выполняется из Python кроссплатформенно;
- [x] SQL-файлы не содержат машинно-зависимых путей;
- [x] реализованы все обязательные витрины;
- [x] для каждой витрины проверены зерно и уникальность ключа;
- [x] SQL-метрики сверены с эталонными Python-расчётами;
- [x] файл базы хранится локально и исключён из Git.

## Этап 5. Исследовательский анализ и визуализация

Результат: воспроизводимый EDA с объяснением структуры потерь.

Критерии готовности:

- [x] описаны объём, период и качество анализируемой выборки;
- [x] изучены SLA, опоздания, прибыльность и компоненты затрат;
- [x] надёжность автомобилей нормализована на километры и часы рейсов;
- [x] выполнены срезы по маршрутам, клиентам, времени и ресурсам;
- [x] графики читаемы и воспроизводимы;
- [x] выводы отделены от наблюдений и ограничений;
- [x] тяжёлая логика вынесена из ноутбука в `src` или `sql`.

## Этап 6. Проверка гипотез

- [x] остальные гипотезы явно помечены как дополнительные;
- [x] проверены предпосылки выбранных статистических методов;

- [x] приведены размер эффекта и интервал неопределённости;
- [x] корреляционные выводы не названы причинными;
- [x] результаты воспроизводятся кодом.
